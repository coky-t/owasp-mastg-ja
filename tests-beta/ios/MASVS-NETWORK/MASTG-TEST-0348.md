## 概要

静的解析は安全でない TLS バージョンを許容する設定を特定することは可能ですが、ライブの通信時に使用される実際のプロトコルを正確に反映できないことがあります。これは、TLS バージョンのネゴシエーションが実行時にクライアント (アプリ) とサーバーの間で行われ、双方でサポートされる最も安全なバージョンを合意するためです。

実際のネットワークトラフィックをキャプチャして解析することで、実際にネゴシエートされ使用されている TLS バージョンを観察できます。このアプローチは、特定の TLS バージョンを強制または制限する可能性のある、サーバーの設定を考慮して、プロトコルのセキュリティの正確な所見を提供します。

静的解析が不完全であったり実施不可能である場合でも、ネットワークトラフィックを調査することで、安全でないバージョン (TLS 1.0 や TLS 1.1 など) が実際に使用されている事例を明らかにできます。

## 手順

1. [アプリのインストール (Installing Apps)](../../../techniques/ios/MASTG-TECH-0056.md) を使用して、アプリをインストールします。
2. [基本的なネットワークモニタリングとスニッフィング (Basic Network Monitoring/Sniffing)](../../../techniques/ios/MASTG-TECH-0062.md) を使用して、アプリトラフィックをキャプチャします。
3. アプリを徹底的に動かして、できるだけ多くのフローをトリガーし、可能な限り機密データを入力します。

## 結果

出力にはアプリトラフィックを含む可能性があります。

## 評価

任意の [安全でない TLS バージョン](../../../Document/0x04f-Testing-Network-Communication.md#recommended-tls-settings) が使用される場合、このテストケースは不合格です。
